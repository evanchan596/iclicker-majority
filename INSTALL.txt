iClicker Majority 2.0.0 - Chrome extension

INSTALL OR UPDATE
1. Extract the ZIP into a folder. Do not load the ZIP itself.
2. Open chrome://extensions and turn on Developer mode.
3. Choose Load unpacked and select the folder containing manifest.json.
   For an existing install, replace its files and click Reload instead.
4. Accept the extension's iClicker site access. Version 2 adds access to
   api.iclicker.com and alarms for background polling.
5. Refresh your iClicker tab, sign in normally, and join the class yourself.
6. For the full fallback chain, prepare Local AI as described below, then
   enable BOTH Local AI fallback and Random fallback in the popup.
7. Click Start auto-select. This permits automatic answer submissions for
   that tab. You can switch tabs and close the popup without stopping it.

ANSWER ORDER
1. LIVE VOTES: read the student reporting API for the exact open question.
   Follow a single leading A-E answer after two consecutive readings.
   "Majority" means the most popular answer, even below 50%.
2. LOCAL AI (if enabled): if a live leader is unavailable or tied, use the
   readable question text/image to ask Chrome's on-device model.
3. RANDOM (if enabled): if there is no usable AI answer, or no readable
   question, select one random enabled letter, not a new letter each tick.

Existing manual answers are preserved by the fallback paths. A live leader
can still replace a manual, AI, or random answer after two readings.
The extension can upgrade its own random answer when AI becomes available.
It does not label AI or random guesses as live votes.
If both fallbacks are off, it waits for readable live votes. Without AI
enabled, a visible tie keeps the current answer rather than guessing.

BACKGROUND TABS
A service-worker scheduler targets a check every five seconds. It sends
wake messages to the original iClicker document, independent of that page's
poll timer. A 30-second alarm recovers scheduling if Chrome suspends the
worker. Multiple checks cannot overlap for the same page.

While running, the extension marks the iClicker tab non-auto-discardable,
then restores its prior setting when stopped. Chrome must stay open and the
computer awake. Forced tab freezing, browser shutdown, crashes, and system
sleep can still interrupt operation. This is not a hard real-time scheduler.
Refreshing or closing the iClicker tab pauses automation; start it again.
Settings are per-page and reset to off on refresh.

If exactly one iClicker tab is running, opening the popup from another tab
shows and controls that running tab. If several are running, open the
specific iClicker tab you want to control. Use one running tab per class.
The extension does not spoof visibility/focus or suppress iClicker events.
iClicker may record when you switch tabs.

LOCAL AI SETUP
Open AI setup from the popup and click Prepare local AI. Keep that setup
tab open; it can be in the background. It hosts the local model because the
model API requires a document context, not a service worker.

The feature uses Chrome's built-in LanguageModel / Prompt API. A supported
desktop Chrome version, compatible hardware, and a model download may be
required. Chrome documents substantial disk and memory requirements at:
https://developer.chrome.com/docs/ai/prompt-api

No external AI account or API key is used. Question content stays on this
computer. If the API is missing, a model cannot be prepared, or that tab
is closed, the popup reports why AI is unavailable and can fall back randomly.
The extension works without AI setup, but cannot independently solve
questions until a compatible on-device model is ready.

AI reads iClicker's displayed extracted question text. It can also use a
rendered question image when the image can be copied safely by the browser
and the local model supports images. Instructor-hidden placeholders are
excluded. Cross-origin images without readable pixel access cannot be used;
if text is also missing, random fallback is used rather than inventing a
question. Unsupported image-only questions cannot be solved automatically.

Question input is size-limited, and AI must return one allowed answer letter.
The engine has a 20-second inference timeout; the worker has a 25-second
response timeout. Invalid/uncertain outputs use the fallback instead.
AI failures are shown explicitly and retried no more than once per 30 seconds
for unchanged question content. Successful answers are cached per question.
AI can be wrong. Question changes, closure, pause, and disabled buttons are
rechecked before clicking, so a delayed AI result cannot submit to a new poll.

LIVE-VOTE ACCESS AND LIMITATIONS
Student API GET requests now run in the service worker with the iClicker
host permission, avoiding page-level CORS restrictions. Requests retain the
student's authentication and include the student client tag. No instructor
credentials, alternate-account access, or access-control bypass is used.

The reporting API must actually expose current question counts to the
student account. Its public client code does NOT prove that a particular
account can access open-poll counts. Results visible only after closure
cannot be used to submit an answer to that closed poll.

Reporting 403/404 errors get a 15-second cooldown before retrying. A failed
report alone can use AI/random fallback after the current question has been
identified and verified. Malformed vote reports are treated as unavailable
in AI mode, never as a live majority; without AI mode they stop automation.
Missing sign-in, denied question/class access, malformed question metadata,
and rate limiting do not trigger blind submission.
Rate limits enforce at least a 60-second pause.

Only individual single-answer A-E polls are supported. No quiz, group,
numeric, text, target, multiple-answer, attendance, or automatic class joining.
The extension does not know whether an answer is correct or guarantee grades.
No live class account was available during development; account-specific
API access and real model quality still depend on your environment.

STATUS AND HISTORY
The popup shows:
- Majority vote visible: Yes and the leader/share, No when unavailable,
  Tied/No votes yet, or Checking/Unknown/Out of date when not current.
- Background polling status, separate from the active tab's focus.
- AI status and reasons it could not read or answer a question.
- The last 200 automatic clicks labeled Live votes, Local AI, or Random.

History includes the question label, chosen letter, time, course identifier,
and live percentage when applicable. The source is fixed when clicked.
A random answer that happens to match a later majority remains Random.
Changing answers creates a separate entry. Repeated checks and manual clicks
do not create entries. History is a record of attempts, not server receipts.
Check iClicker's own confirmation to know an answer was accepted.

History stays in this browser profile, not Chrome Sync. Clear history deletes
stored entries without stopping future automation. Uninstalling clears it.
If saving a selection fails, automation pauses and reports the failure.

PRIVACY AND PERMISSIONS
Site access is limited to student.iclicker.com and api.iclicker.com.
The existing session token is passed only to the extension worker and then
to the fixed api.iclicker.com host for allowed student GET routes. Tokens
are not saved or logged. Redirects and arbitrary request URLs are rejected.

Question text/images are passed only to the extension's on-device AI page
and retained only in memory. They are not included in history, uploaded to
an AI server, or exported. Chrome may download its local model.
History stores identifiers, short question labels, letters, sources, times,
and live percentages, not images or complete vote distributions.
Session storage holds scheduler metadata so a worker restart can recover.

No analytics, third-party scripts, credential scraping, or focus spoofing.
Use only where your course permits automation. This extension is independent
of iClicker, Macmillan, and ByeClicker.

DEVELOPMENT
Run node --test from this folder (Node.js 18+). No build or package install.
Load the folder as an unpacked extension in Chrome 120+; local AI requires
a newer compatible Chrome version and hardware.
